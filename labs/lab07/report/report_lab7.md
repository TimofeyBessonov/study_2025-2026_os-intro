## **2\. Назначение прав доступа с помощью команды chmod**

Для указанных в задании каталогов и файлов рассчитали необходимые маски прав доступа в восьмеричном и символьном представлениях и применили команду chmod:

> 1. Каталог australia с правами drwxr--r-- (владелец: rwx, группа: r--, остальные: r--): Восьмеричный код: 744\.  
>    `mkdir australia`  
>    `chmod 744 australia`  
>    `# Символьный аналог: chmod u=rwx,g=r,o=r australia`

> 2. Каталог play с правами drwx--x--x (владелец: rwx, группа: \--x, остальные: \--x): Восьмеричный код: 711\.  
>    `mkdir play`  
>    `chmod 711 play`  
>    `# Символьный аналог: chmod u=rwx,g=x,o=x play`

> 3. Файл my\_os с правами \-r-xr--r-- (владелец: r-x, группа: r--, остальные: r--): Восьмеричный код: 544\.  
>    `touch my_os`  
>    `chmod 544 my_os`  
>    `# Символьный аналог: chmod u=rx,g=r,o=r my_os`

> 4. Файл feathers с правами \-rw-rw-r-- (владелец: rw-, группа: rw-, остальные: r--): Восьмеричный код: 664\.  
>    `touch feathers`  
>    `chmod 664 feathers`  
>    `# Символьный аналог: chmod u=rw,g=rw,o=r feathers`

## **3\. Практические упражнения с файловой структурой и правами**

Просмотрели файл системных учетных записей /etc/passwd (в задании /etc/password):  
`cat /etc/passwd`

Скопировали файл \~/feathers в файл \~/file.old, после чего переместили его в каталог \~/play:  
`cp ~/feathers ~/file.old`  
`mv ~/file.old ~/play/`

Скопировали рекурсивно каталог \~/play в директорию \~/fun, затем переместили каталог \~/fun внутрь \~/play с новым именем games:  
`cp -r ~/play ~/fun`  
`mv ~/fun ~/play/games`

Лишили владельца файла \~/feathers права на чтение:  
`chmod u-r ~/feathers`  
`ls -l ~/feathers`

Проверили поведение команд cat и cp при попытке чтения файла без права r:  
`cat ~/feathers`  
`# Ошибка: cat: feathers: Permission denied`  
`cp ~/feathers ~/test_copy`  
`# Ошибка: cp: cannot open 'feathers' for reading: Permission denied`

*Вывод:* отсутствие права на чтение (r) блокирует доступ к содержимому файла как для вывода на экран, так и для создания его копии.  
Вернули владельцу файла право на чтение:  
`chmod u+r ~/feathers`

Лишили владельца каталога \~/play права на выполнение (x) и попытались войти в него:  
`chmod u-x ~/play`  
`cd ~/play`  
`# Ошибка: bash: cd: /home/trbessonov/play: Permission denied`

*Вывод:* бит выполнения (x) на каталоге определяет возможность войти в него и сделать его текущим рабочим каталогом. При отсутствии этого права перейти в директорию нельзя.  
Восстановили владельцу каталога право на выполнение:  
`chmod u+x ~/play`

## **4\. Характеристика системных команд (mount, fsck, mkfs, kill)**

С помощью команды man изучили назначение и опции утилит системного уровня:

> * **mount:** утилита подключения файловой системы накопителя или сетевого ресурса к указанной точке монтирования в общей иерархии. *Пример:* mount \-o ro /dev/sdb1 /mnt/data (монтирование раздела /dev/sdb1 в каталог /mnt/data в режиме только для чтения).  
> * **fsck (File System Consistency Check):** утилита проверки и восстановления целостности файловых систем. *Пример:* fsck \-y /dev/sdb1 (автоматическое устранение найденных повреждений на разделе).  
> * **mkfs (Make File System):** форматирование раздела и создание целевой файловой системы. *Пример:* mkfs.ext4 /dev/sdb1 или mkfs \-t btrfs /dev/sdb2.  
> * **kill:** утилита отправки сигналов процессам операционной системы по их PID. *Пример:* kill \-15 1234 (вежливый запрос на завершение SIGTERM), kill \-9 1234 (принудительное аварийное уничтожение SIGKILL).

# **Ответы на контрольные вопросы**

> 1. **Дайте характеристику каждой файловой системе, существующей на жёстком диске компьютера, на котором вы выполняли лабораторную работу.**  
   * **Btrfs:** основная корневая файловая система Fedora, использующая механизм Copy-on-Write (CoW), встроенное сжатие данных (zstd) и поддержку моментальных снимков (snapshots).  
   * **ext4:** стабильная классическая журналируемая файловая система, применяемая для загрузочного раздела /boot.  
   * **vfat (FAT32):** используется для системного раздела EFI (/boot/efi) для совместимости со спецификацией UEFI.  
   * **tmpfs:** виртуальная временная файловая система в оперативной памяти для каталогов /tmp, /run, /dev/shm.  
   * **sysfs / proc:** виртуальные псевдо-ФС ядра для доступа к параметрам устройств и процессов.  
> 2. **Приведите общую структуру файловой системы и дайте характеристику каждой директории первого уровня.**  
   * / — корень всей иерархии файловой системы.  
   * /bin (символическая ссылка на /usr/bin) — основные исполняемые бинарные файлы команд ОС.  
   * /sbin (ссылка на /usr/sbin) — исполняемые файлы системного администрирования.  
   * /etc — статические конфигурационные файлы системы и установленных сервисов.  
   * /home — домашние каталоги рядовых пользователей.  
   * /root — домашний каталог суперпользователя.  
   * /dev — файлы блочных и символьных устройств.  
   * /proc и /sys — виртуальные каталоги информации ядра и процессов.  
   * /tmp — временные файлы, доступные для записи всем пользователям.  
   * /var — динамически изменяемые данные (логи, кэши, почтовые очереди).  
   * /usr — пользовательские программы, библиотеки, документация.  
   * /mnt и /media — точки временного монтирования сменных носителей и дисков.  
> 3. **Какая операция должна быть выполнена, чтобы содержимое некоторой файловой системы было доступно операционной системе?** Операция **монтирования** (mount), которая связывает корневую директорию файловой системы на физическом носителе с определенной существующей директорией (точкой монтирования) в общем дереве каталогов ОС.  
> 4. **Назовите основные причины нарушения целостности файловой системы. Как устранить повреждения?**  
   * *Причины:* внезапное отключение электропитания, аппаратные сбои накопителя (bad-блоки), системные зависания ядра, некорректное извлечение накопителя без размонтирования (umount).  
   * *Устранение:* отмонтировать поврежденный раздел и запустить проверку утилитой fsck \<устройство\> с ключами автовосстановления (-y или \-a).  
> 5. **Как создаётся файловая система?** Создание выполняется командой форматирования mkfs (Make File System) с указанием типа ФС и целевого раздела накопителя: mkfs \-t ext4 /dev/sdb1 или с помощью специализированных утилит mkfs.xfs, mkfs.btrfs.  
> 6. **Дайте характеристику командам для просмотра текстовых файлов.**  
   * cat — непрерывный вывод содержимого всего файла в терминал (удобен для малых файлов).  
   * less — постраничный двунаправленный просмотр файлов любого размера с поддержкой навигации и поиска.  
   * head — вывод первых N строк файла (по умолчанию 10).  
   * tail — вывод последних N строк файла (по умолчанию 10), флаг \-f позволяет отслеживать изменения лога в реальном времени.  
> 7. **Приведите основные возможности команды cp в Linux.** Команда cp предназначена для копирования файлов и каталогов. Основные возможности:  
   * Копирование одиночных и множественных файлов в каталог;  
   * Рекурсивное копирование деревьев каталогов (-r, \-R);  
   * Сохранение исходных атрибутов, прав и временных меток (-p, \-a);  
   * Интерактивный запрос перед перезаписью существующих файлов (-i);  
   * Создание жестких (-l) и символических (-s) ссылок вместо копирования.  
> 8. **Приведите основные возможности команды mv в Linux.** Команда mv служит для перемещения и переименования файлов и каталогов. Основные возможности:  
   * Переименование файла/каталога в пределах одной файловой системы без перезаписи данных на диске;  
   * Перемещение файлов и папок в другой целевой каталог;  
   * Защита от случайной перезаписи существующих файлов (опция \-i);  
   * Запрет перезаписи файлов с флагом \-n (--no-clobber).  
> 9. **Что такое права доступа? Как они могут быть изменены?** Права доступа — это набор атрибутов, определяющих полномочия на чтение (r), запись (w) и выполнение (x) для трех категорий пользователей: владельца (u), членов группы владельца (g) и всех остальных (o). Они могут быть изменены владельцем файла или суперпользователем root с помощью утилиты chmod:  
   * В символьном виде: chmod u+x,g-w file;  
   * В восьмеричном виде: chmod 755 file.

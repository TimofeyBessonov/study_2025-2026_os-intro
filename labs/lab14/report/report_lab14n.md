\#\# 1\. Задание 1\. Упрощённый механизм семафоров

\*\*Задача.\*\* Написать командный файл, реализующий упрощённый механизм семафоров. Скрипт в течение времени \`t1\` дожидается освобождения ресурса, выдавая об этом сообщение; дождавшись, использует его в течение \`t2 \< t1\`, также выдавая сообщение. Запустить скрипт в одном терминале в фоне с перенаправлением вывода в другой терминал (\`\> /dev/tty\#\`), где также запущен этот файл, но на переднем плане. Доработать программу для взаимодействия трёх и более процессов.

\*\*Листинг \`semaphore.sh\`:\*\*

\`\`\`bash  
\#\!/bin/bash

\# Использование: ./semaphore.sh \<имя\_семафора\> \<t1\_ожидание\> \<t2\_использование\> \[терминал\]  
\# Пример:       ./semaphore.sh mylock 10 5 /dev/pts/3

SEMFILE="\${1:-lockfile}"     \# файл-семафор  
T1="\${2:-10}"                 \# время ожидания освобождения (сек)  
T2="\${3:-5}"                  \# время использования ресурса (сек)  
TTY="\${4:-/dev/tty}"          \# куда перенаправлять вывод

PID=\$\$

\# Сообщение о процессе (с указанием PID — для различия нескольких процессов)  
msg() {  
    echo "\[PID=\$PID\] $*">"$TTY"  
}

msg "Процесс запущен. Ожидание ресурса (семафор: \$SEMFILE)..."

\# Ожидание освобождения ресурса: пока файл семафора существует  
ELAPSED=0  
while \[ \-e "\$SEMFILE" \]; do  
    if \[ "$ELAPSED"-ge"$T1" \]; then  
        msg "Превышено время ожидания (\$T1 с). Завершение."  
        exit 1  
    fi  
    msg "Ресурс занят. Ждём... ($ELAPSED/$T1 с)"  
    sleep 1  
    ELAPSED=\$((ELAPSED \+ 1))  
done

\# Захват ресурса: создаём файл-семафор (атомарная операция noclobber)  
if (set \-o noclobber; echo "$PID">"$SEMFILE") 2\>/dev/null; then  
    msg "Ресурс захвачен. Использование в течение \$T2 с."  
else  
    msg "Не удалось захватить ресурс (гонка). Завершение."  
    exit 2  
fi

\# Критическая секция  
for ((i \= T2; i \> 0; i--)); do  
    msg "Работаю с ресурсом... осталось \${i} с"  
    sleep 1  
done

\# Освобождение ресурса  
rm \-f "\$SEMFILE"  
msg "Ресурс освобождён. Завершение работы."  
exit 0  
\`\`\`

\*\*Запуск в двух терминалах (взаимодействие двух процессов):\*\*

В первом терминале (\`/dev/pts/2\`):  
\`\`\`bash  
chmod \+x semaphore.sh  
./semaphore.sh mylock 15 8 /dev/pts/2  
\`\`\`

Во втором терминале (\`/dev/pts/3\`), в фоне, с перенаправлением вывода в первый:  
\`\`\`bash  
./semaphore.sh mylock 20 5 /dev/pts/2 &  
\`\`\`

\*\*Модификация для трёх и более процессов.\*\* Механизм семафора обобщается естественным образом: достаточно запустить скрипт несколько раз с одним и тем же именем семафора. Атомарность захвата обеспечивается опцией \`noclobber\`, которая создаёт файл только если он ещё не существует, тем самым исключая одновременный захват двумя процессами.

Пример запуска трёх процессов:

\`\`\`bash  
./semaphore.sh mylock 30 5 /dev/pts/2 &  
./semaphore.sh mylock 30 5 /dev/pts/2 &  
./semaphore.sh mylock 30 5 /dev/pts/2 &  
wait  
\`\`\`

Каждый процесс по очереди захватывает \`mylock\`, работает заданное время и освобождает его, а остальные в это время ждут, выводя сообщения об ожидании.

\#\# 2\. Задание 2\. Собственная реализация команды man

\*\*Задача.\*\* Реализовать команду \`man\` с помощью командного файла. В каталоге \`/usr/share/man/man1\` находятся архивы текстовых файлов со справкой по большинству установленных программ. Каждый архив можно открыть командой \`less\` и сразу просмотреть содержимое. Командный файл должен принимать в качестве аргумента название команды и выдавать справку либо сообщение об отсутствии справки.

\*\*Предварительное изучение каталога:\*\*

\`\`\`bash  
ls /usr/share/man/man1 | head \-n 20  
file /usr/share/man/man1/ls.1.gz  
\`\`\`

Файлы обычно имеют расширение \`.1.gz\` (сжатый man-страницы раздела 1 — пользовательские команды).

\*\*Листинг \`myman.sh\`:\*\*

\`\`\`bash  
\#\!/bin/bash

MAN\_DIR="/usr/share/man/man1"

if \[ \$\# \-ne 1 \]; then  
    echo "Использование: \$0 \<имя\_команды\>" \>&2  
    exit 1  
fi

CMD="\$1"  
FILE="$MA{N}_{D}IR/$CMD.1.gz"

\# Проверяем наличие справки (поддерживаем и .gz, и обычный .1)  
if \[ \-f "\$FILE" \]; then  
    zcat "\$FILE" | less  
elif \[ \-f "$MA{N}_{D}IR/$CMD.1" \]; then  
    less "$MA{N}_{D}IR/$CMD.1"  
else  
    echo "Справка для команды '\$CMD' не найдена в \$MAN\_DIR" \>&2  
    exit 2  
fi

exit 0  
\`\`\`

\*\*Команды для запуска:\*\*

\`\`\`bash  
chmod \+x myman.sh  
./myman.sh ls  
./myman.sh grep  
./myman.sh несуществующая\_команда  
\`\`\`

\*\*Замечание.\*\* Многие man-страницы хранятся в сжатом виде (\`.gz\`), поэтому используется \`zcat\` для распаковки «на лету» и передачи результата в \`less\`. Если в системе установлена утилита \`less\`, она корректно отображает текст с постраничной навигацией.

\#\# 3\. Задание 3\. Генератор случайных латинских букв

\*\*Задача.\*\* Используя встроенную переменную \`$RANDOM`,написатькомандныйфайл,генерирующийслучайнуюпоследовательностьбуквлатинскогоалфавита.Учесть,что`$RANDOM\` выдаёт псевдослучайные числа в диапазоне от 0 до 32767\.

\*\*Идея.\*\* Каждой букве латинского алфавита (\`a\`–\`z\`, 26 букв) можно сопоставить число от 0 до 25\. Тогда достаточно взять \`\$RANDOM % 26\` и прибавить ASCII-код буквы \`a\`. Полученный код преобразуется в символ с помощью \`printf "\\\\\$(printf '%03o' \$code)"\` или встроенного механизма bash.

\*\*Листинг \`random\_letters.sh\`:\*\*

\`\`\`bash  
\#\!/bin/bash

\# Использование: ./random\_letters.sh \<длина\_последовательности\> \[количество\_строк\]  
\# Пример:       ./random\_letters.sh 20 3

LEN="\${1:-10}"  
LINES="\${2:-1}"

if \! \[\[ "$LEN"={~}^{[}0-9]+$ \]\] || \[ "\$LEN" \-le 0 \]; then  
    echo "Ошибка: длина должна быть положительным целым числом" \>&2  
    exit 1  
fi

\# Функция генерации одной строки случайных букв  
random\_string() {  
    local n="\$1"  
    local out=""  
    local i  
    for ((i \= 0; i \< n; i++)); do  
        \# \$RANDOM — от 0 до 32767, берём остаток по модулю 26  
        local idx=\$((RANDOM % 26))  
        \# ASCII-код 'a' \= 97, поэтому 97 \+ idx даёт 'a'...'z'  
        local code=\$((97 \+ idx))  
        \# Преобразуем код в символ и добавляем к результату  
        out+=\$(printf "\\\\\$(printf '%03o' "\$code")")  
    done  
    echo "\$out"  
}

\# Генерация заданного числа строк  
for ((j \= 1; j \<= LINES; j++)); do  
    random\_string "\$LEN"  
done  
\`\`\`

\*\*Команды для запуска:\*\*

\`\`\`bash  
chmod \+x random\_letters.sh  
./random\_letters.sh 15  
./random\_letters.sh 20 5  
\`\`\`

\*\*Пример вывода:\*\*

\`\`\`  
kqzmvbnrtyuioppas  
wqertyuioasdfghjklz  
\`\`\`

\*\*Пояснение.\*\* Выражение \`$((RANDOM%26))`даётравномернораспределённоечислоот0до25.Прибавление97(ASCII-кодсимвола`a`)ипреобразованиечерез`printf`даётсоответствующуюстрочнуюлатинскуюбукву.Длязаглавныхбуквдостаточнозаменить97на65(ASCII-код`A`).Таккак`$RANDOM\` выдаёт числа до 32767, остаток по модулю 26 даёт небольшое смещение распределения, но для учебных целей это допустимо.

\# Ответы на контрольные вопросы

\*\*1. Найдите синтаксическую ошибку в следующей строке:\*\*

\`\`\`bash  
while \[\$i \!= "exit"\]  
\`\`\`

\*\*Ошибка:\*\* в bash квадратные скобки \`\[ ... \]\` — это встроенная команда (синоним \`test\`), и она требует \*\*пробелов\*\* между \`\[\`, операндами и \`\]\`. Кроме того, переменную \`\$i\` следует заключать в двойные кавычки для безопасности.

\*\*Правильно:\*\*

\`\`\`bash  
while \[ "\$i" \!= "exit" \]  
\`\`\`

Без пробелов \`\[$i`интерпретируетсякаккомандасименем`[$i\` (или \`\[значение\`), которой не существует, и оболочка выдаст ошибку \`command not found\`.

\*\*2. Как объединить (конкатенация) несколько строк в одну?\*\*

В bash строки объединяются простым написанием подряд, без оператора:

\`\`\`bash  
s1="Hello, "  
s2="world\!"  
s3="$s1$s2"           \# "Hello, world\!"  
s4="$s1${s2}"       \# эквивалентно, явные границы переменных  
s5="prefix"\$s1"suffix"  
\`\`\`

Также можно использовать оператор \`+=\` для добавления к переменной:

\`\`\`bash  
s="abc"  
s+="def"              \# s \== "abcdef"  
\`\`\`

\*\*3. Найдите информацию об утилите seq. Какими иными способами можно реализовать её функционал при программировании на bash?\*\*

\*\*\`seq\`\*\* — утилита, генерирующая последовательность чисел:

\`\`\`bash  
seq 1 10               \# 1 2 3 ... 10  
seq 1 2 9              \# 1 3 5 7 9 (с шагом 2\)  
seq \-w 1 5             \# 01 02 03 04 05 (с выравниванием нулями)  
seq \-s ", " 1 5        \# 1, 2, 3, 4, 5 (с разделителем)  
\`\`\`

\*\*Альтернативы в чистом bash (без внешней утилиты):\*\*

\- Фигурные скобки (brace expansion):  
  \`\`\`bash  
  for i in {1..10}; do echo "\$i"; done  
  for i in {1..10..2}; do echo "\$i"; done   \# шаг 2  
  \`\`\`  
\- C-подобный цикл \`for\`:  
  \`\`\`bash  
  for ((i \= 1; i \<= 10; i++)); do echo "\$i"; done  
  \`\`\`  
\- Цикл \`while\` со счётчиком:  
  \`\`\`bash  
  i=1  
  while \[ "\$i" \-le 10 \]; do  
      echo "\$i"  
      i=\$((i \+ 1))  
  done  
  \`\`\`  
\- Команда \`printf\` в связке с \`eval\` (для экзотических случаев).

\*\*4. Какой результат даст вычисление выражения \`\$((10/3))\`?\*\*

Результат: \*\*3\*\*. В bash арифметические операции над целыми числами выполняются с \*\*целочисленным делением\*\* (дробная часть отбрасывается). Для получения вещественного результата необходимо использовать внешние утилиты (\`bc\`, \`awk\`) или \`printf\` с плавающей точкой.

\*\*5. Укажите кратко основные отличия командной оболочки zsh от bash.\*\*

| Признак | bash | zsh |  
|---------|------|-----|  
| Автодополнение | базовое | расширенное (по истории, по контексту, с подсветкой) |  
| Исправление опечаток | нет | встроенное (spell correction) |  
| Глоббинг | стандартный | расширенный (\`\*\*\`, квалификаторы) |  
| Тема оформления | нет встроенной | поддержка через \`oh-my-zsh\` и др. |  
| Массивы | индексируются с 0 | индексируются с 1 (по умолчанию) |  
| Совместимость | POSIX-совместимая | почти совместима, но есть отличия |  
| Плагины | ограниченно | развитая экосистема плагинов |  
| Поддержка тем | нет | есть |  
| Настройка промпта | \`PS1\` | мощный механизм \`PROMPT\`/\`RPROMPT\` |  
| Стандартность | повсеместно в Linux | чаще у продвинутых пользователей |

zsh удобнее для интерактивной работы, bash — стандарт де\-факто для скриптов (особенно с shebang \`\#\!/bin/bash\`).

\*\*6. Проверьте, верен ли синтаксис данной конструкции:\*\*

\`\`\`bash  
for ((a=1; a \<= LIMIT; a++))  
\`\`\`

\*\*Синтаксис верен для bash\*\*, но:

\- Конструкция \`for ((...))\` — это \*\*bash-специфичное\*\* расширение (C-подобный цикл). В POSIX-совместимом \`sh\` она не поддерживается.  
\- Требуется ключевое слово \`do ... done\`:  
  \`\`\`bash  
  for ((a=1; a \<= LIMIT; a++)); do  
      echo "\$a"  
  done  
  \`\`\`  
\- Переменная \`LIMIT\` должна быть определена и содержать целое число, иначе цикл не выполнится или завершится с ошибкой.  
\- Двойные круглые скобки \`(( ))\` допускают пробелы и арифметические выражения.

\*\*7. Сравните язык bash с какими-либо языками программирования. Какие преимущества у bash по сравнению с ними? Какие недостатки?\*\*

\*\*Сравнение с Python:\*\*

| Критерий | bash | Python |  
|----------|------|--------|  
| Запуск и окружение | доступен везде в UNIX | требует интерпретатора |  
| Работа с процессами | прямой вызов команд | через \`subprocess\` |  
| Работа с файлами | прямой доступ | через модули |

| Обработка ошибок | коды возврата | исключения |  
| Читаемость | ниже для сложной логики | выше |

\*\*Преимущества bash:\*\*  
\- повсеместно доступен в UNIX/Linux без установки;  
\- идеален для системного администрирования и автоматизации;  
\- прямой доступ к командам и утилитам ОС;  
\- лаконичен для типовых задач (копирование, архивация, запуск);  
\- не требует компиляции.

\*\*Недостатки bash:\*\*  
\- слабая типизация и отсутствие структур данных (кроме массивов);  
\- медленные арифметические вычисления;  
\- сложная обработка ошибок (только коды возврата);  
\- экранирование метасимволов — частый источник ошибок;  
\- плохая читаемость длинных скриптов;  
\- нет полноценных функций с локальными переменными (только эмуляция через \`local\`);  
\- не подходит для сложной бизнес-логики.

\# Заключение

1\. Реализован упрощённый механизм семафоров на языке bash с использованием файла-семафора и атомарной операции создания через \`noclobber\`. Показана работа двух, трёх и более процессов, синхронизирующих доступ к общему ресурсу.  
2\. Разработана собственная реализация команды \`man\`, работающая с каталогом \`/usr/share/man/man1\` и утилитой \`less\` (в том числе с распаковкой \`.gz\` через \`zcat\`).  
3\. Написан генератор случайных латинских букв на основе встроенной переменной \`\$RANDOM\` с преобразованием чисел в ASCII-символы через \`printf\`.  
4\. Освоены приёмы взаимодействия процессов, работы с системными каталогами и генерации псевдослучайных данных в bash.  
5\. Все поставленные задачи выполнены, цель работы достигнута.
